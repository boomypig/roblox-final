# Changelog

Notable changes to the toolkit. Dates are YYYY-MM-DD. Changes to what a gate accepts are
marked **Gate change**.

## Unreleased

### Added
- `docs/workflow.md` is now the one path from idea to published game: every step with what runs
  it, what it reads and writes, and the gate that ends it, plus the operating policy every
  skill and agent follows.
- Gates for the design-side steps: `pitch/scripts/check_pitch.py`,
  `art-brief/scripts/check_brief.py`, `build/scripts/check_spec.py`.
- `docs/structure.md` (the five parts of every skill and agent, with a coverage table),
  `docs/redundancy-map.md`, `docs/vault-readers.md`, `docs/migration.md`.
- `tools/migrate_game.py <game dir> [--write]`: rewrites a game repo's references to moved
  toolkit paths.
- `vault/CATALOG.md`: the full read-when line and status of every research file.

- `roblox-map/scripts/luau/map_checks.lua` and `map_checks.py`: the map-builder's checks after
  each structure (inventory, property sweep, lane widths and hiding-spot sizes by raycast,
  refuge distance on a floor grid), one line per failure, capped at 30.
- `roblox-map/references/map-state.template.md`: a per-map state file the map-builder reads
  first and updates last, with a "Run in progress" section so a cut-off run resumes.
- Agent cards generated by `tools/build_cards.py`: `roblox-map/references/builder-card.md` and
  `build/references/reviewer-card.md`, each with a coverage table and source hashes.

- `tools/new_game.py` is the one command that makes a game: the code scaffold, the contract,
  `design/layout.json`, the starter docs, a `CLAUDE.md` that is a task -> file list, the Stop
  hook and the first `HANDOFF.md`. `create-roblox-game/scripts/new_game.py` forwards to it.
- `design/layout.json`, the layout map: where a game keeps its boot scripts, services, remotes,
  config, pure rules, tests, packages and tool manifest (`roblox-code/references/layout.md`,
  read by `roblox-code/scripts/layout.py`).
- `create-roblox-game/scripts/adopt.py` and `references/adopt.md`: take on a game made before
  the toolkit. Read-only by default; `--write` adds the layout map, a contract skeleton filled
  from the game's docs and the starter files, and never touches its code. A fixture of such a
  game is in `tests/fixtures/adopted-game/`.
- `create-roblox-game/scripts/session.py` and the starter's Stop hook: a session ends at a
  boundary (a section closes, one map pass reports, one /build passes) with `HANDOFF.md`
  written, and the session's gate failures, stalls, fallbacks, interventions and debts are
  appended to `private/lessons-inbox.md`.
- `section.py handoff --light build|map`: a five-heading handoff for one /build or one map pass.
- `/toolkit-retro` and `toolkit-retro/scripts/inbox.py`: run only when asked; each lesson in
  `private/lessons-inbox.md` becomes one edit to its owning skill with a test, or is closed as
  the game's own debt with a reason.
- `tools/toolkit_lint.py` (in CI): duplicated rules, dead paths and line references, stale
  cards, untested scripts and private data; fails only on findings not in its baseline.
- Studio facts: the built-in server's tool list refreshed (`create-roblox-game/references/mcp.md`),
  `save_place` documented (it never publishes), and the unverified capture and undo claims
  listed with the test for each (`roblox-map/references/studio-mcp.md`).
- `tools/smoke.py`: makes a game in a temp folder and runs the four gates, `validate.py`, every
  `section.py` command, the Stop hook and adoption. CI installs the gate tools and runs it.

### Changed
- `tools/migrate_game.py` reads its list of moves from `docs/migration.md`, so the old paths are
  written down in one place; `tests/test_public_tree.py` and `tests/test_private_optional.py`
  are back to their original allowlists, and the doc-link check is `tests/test_doc_links.py`.
- `/build` and `check.py` read `design/layout.json`: `check.py` takes the tests folder, Wally use,
  tool manifest and lint and format paths from it; `/build` puts code where the layout says.
- The starter's `architecture.md` points at the layout map and the roblox-code rules instead of
  restating them; every placeholder says which step fills it.
- `/art-brief`, `/build` and the spec-writer no longer stop to ask. Open points are decided and
  written as `**Assumption:**` lines or judgment calls; the user approves once.
- **Gate change.** `/build` refuses a spec that is not approved or has no checkable acceptance
  criteria (`check_spec.py --require-approved`).
- **Gate change 2.** `section.py close 1` accepts its ledger stages ended
  `run_log.py end --status adopted` (an adopted game's research and design were done before the
  toolkit; the status needs no `start`). `validate.py` must still pass, and no other section
  accepts `adopted`.
- Seven build references moved from `vault/fundamentals/` to the owning skill's `references/`
  (quality bar, security, UI, game feel, visual quality, performance, Studio MCP). Paths are in
  `docs/migration.md`. `vault/INDEX.md` stays at the same path and is now the short index.
- `tools/vault_lint.py` reads its file list from `vault/CATALOG.md` and lints the moved
  references with the same rules.
- The reviewer reports the output of `validate.py` and `verify_wired.py` instead of repeating
  their checks.

### Fixed
- The build checklist said Ctrl+S publishes. Saving never publishes; the first save of a new
  place opens a dialog that creates the experience on the account.
- `roblox-code/scripts/check.py` required `Packages/` in every project; it is required only
  when `wally.toml` exists.
- `check.py` passed a gate when a rokit shim ran for a tool the game had not pinned (the shim
  prints an error and exits 0). That is now a FAIL naming the tool and the line to add to
  `rokit.toml` (or `aftman.toml`).
- **Gate change.** `section.py resume` no longer writes an implied approval into
  `design/sections.json`. It prints `section.py approve N --implied`, which writes the same
  record.
- `validate.py` and `section.py close` rejected any value or HANDOFF line containing "TODO", so
  a game titled "TODO List Tycoon" could not pass. Only values that start with a scaffold
  marker (`TODO`, `TODO:`, `TODO<Name>`) count, and the report shows the first 40 characters.

- The map-builder reads its card, the state file and the zone's reference images instead of
  three full references; it runs `map_checks.lua` after each structure and reports the numbers.
  It may write its state file only.
- The reviewer reads its card and the game's `design/layout.json` when it exists, instead of
  assuming `Net.luau` and `Core/`. The spec-writer reads the short index and `docs/decisions.md`
  in full, and can run its gate.
- The Studio batch example runs inside `pcall` and always finishes its undo recording
  (`Cancel` on error).

### Removed
- `starter/docs/workflow.md`: a game points at the toolkit's workflow doc instead of carrying
  a copy. `starter/docs/tech/conventions.md` no longer restates the `roblox-code` rules.

## 0.1.0 - 2026-11-17

First public version.

### Added
- `README.md` for a new reader, `CONTRIBUTING.md`, `NOTICE.md`, this changelog and
  `docs/decisions.md`.
- `goals.template.md`: the template for your own goals file.
- `tests/`: checks that the tracked tree holds no personal names, emails or machine paths, no
  path to a file that moved, and that everything still works when `private/` is absent.
- A GitHub Actions workflow that runs the tests and the vault lint.

### Changed
- Personal material lives in `private/`, which git ignores: the goals file, pitches, generated
  trend reports, the tracker database, cache and log, and the case studies of named games.
  Every skill, agent and script that reads one of them says what it does when the file is
  missing and carries on.
- The trends tracker writes its report to `private/trends/` and keeps its database in
  `private/trends/data/`. `report --out DIR` replaces `report --vault DIR`, which still works.
  `ROBLOX_FINAL_PRIVATE` moves the folder. The client's User-Agent names the tool only; set
  `TRENDS_CONTACT` to add contact details.
- The vault cites case studies as `(case study: <slug>)` instead of linking to them, so a clone
  has no dead links. `tools/vault_lint.py` checks the markers when the case studies are present
  and passes without them.
- `tools/vault_apicheck.py` caches the API dump in `tools/.cache/`.
